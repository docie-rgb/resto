# 배틀쉽 (Battleship)

플레이어 vs CPU 턴제 해전 게임입니다. HTML / CSS / JavaScript만 사용하며 외부 라이브러리와 서버가 필요 없습니다.

## 실행 방법

- `battleship/index.html`을 Chrome, Whale 등 최신 브라우저로 열면 바로 실행됩니다. (더블클릭)
- 블로그 배포 후에는 https://docie-rgb.github.io/resto/battleship/ 에서 플레이할 수 있습니다.
- 로직 테스트는 `battleship/test.html`을 브라우저로 열면 자동 실행되고 결과가 화면에 표시됩니다.

## 조작법

1. 화면을 열면 양측 함대가 무작위로 배치됩니다. 왼쪽이 내 함대, 오른쪽이 CPU 함대입니다.
2. 배치가 마음에 들지 않으면 **배치 변경**을 누릅니다. (시작 전에만 가능)
3. **게임 시작**을 누르면 플레이어가 먼저 공격합니다.
4. 오른쪽 CPU 격자에서 공격할 칸을 클릭합니다.
   - 명중(빨간 X)하면 한 번 더 공격합니다. 빗나가면(흰 점) CPU 차례가 됩니다.
   - 함선을 격침하면 진한 빨간색으로 표시되고, 주변 1칸은 확인된 바다(흐린 점)로 자동 표시됩니다.
5. 자기 턴이 5번 시작될 때마다 핵폭탄 1개를 얻습니다(최대 1개 보유). 첫 턴과, 상대에게 넘어갔던 턴이 다시 돌아올 때만 게이지가 오르고, 명중으로 이어지는 추가 공격은 같은 턴이라 오르지 않습니다. 하단의 ☢ 아이콘과 점 5개가 보유량과 진행도입니다.
   - **핵폭탄 사용** → CPU 격자 위에서 주황색 3×3 범위를 보고 중심 칸을 클릭합니다.
   - 새로 공격할 칸이 없는 범위는 회색으로 표시되며 사용할 수 없습니다.
   - **취소** 버튼 또는 `Esc`로 조준을 취소합니다.
6. 상대 함선 10척을 모두 격침하면 VICTORY, 내 함선이 모두 격침되면 DEFEAT입니다. **다시 시작**으로 새 게임을 시작합니다.

## 파일 구성

| 파일 | 역할 |
| --- | --- |
| `index.html` | 화면 구조 (상단 턴 표시, 좌우 격자, 하단 핵폭탄 상태·버튼) |
| `style.css` | 색상, 격자, 표시 상태, 효과 애니메이션 |
| `game.js` | 게임 규칙 (DOM 없음). `window.Battleship` |
| `ai.js` | CPU 공격 전략. `window.BattleshipAI` |
| `ui.js` | 렌더링, 입력 처리, 연출 타이밍과 CPU 턴 예약 |
| `sound.js` | 효과음. Web Audio API로 직접 합성 (빗나감: 첨벙, 명중: 타격음, 핵폭탄: 폭발음). `window.BattleshipSound` |
| `ships.js` | 함선 이미지(SVG). 5칸 항공모함, 4칸 전함, 3칸 순양함, 2칸 구축함. `window.BattleshipShips` |
| `test.html` | 로직 자동 테스트 (PRD 14장 기준) |

### game.js 주요 함수

| 함수 | 설명 |
| --- | --- |
| `placeFleet(rng)` | 큰 함선부터 가능한 위치를 모두 구해 섞어 시도하고, 막히면 되돌아가는 백트래킹 배치. 후보가 유한해 무한 반복이 없음 |
| `attackCell(board, i)` | 한 칸 판정. 마지막 칸 명중 시 한 번만 격침 처리하고 주변을 확인된 바다로 표시 |
| `publicView(board)` | 공격자가 알 수 있는 정보(미확인/빗나감/명중/격침/확인된 바다, 남은 함선 길이)만 추출. CPU는 이것만 사용 |
| `Game#fire(attacker, i)` | 일반 포격. 상태·재공격 검사, 포격 횟수 기록 |
| `Game#_beginTurn(side)` | 턴이 시작될 때(첫 턴, 상대에게서 공격권이 돌아올 때) 핵폭탄 게이지 +1, 5가 되면 지급 |
| `Game#nuke(attacker, center)` | 3×3 핵폭탄. 격자 밖·이미 공격한 칸 제외, 새 대상이 없으면 거부 |
| `Game#_afterAttack` | 승패 확인 후 명중이면 같은 진영, 아니면 상대에게 공격권 |
| `Game#finishResolve()` | 결과 연출(`RESOLVING_ATTACK`)이 끝난 뒤 다음 차례로 전환 |

게임 상태: `READY` → `PLAYER_TURN` ⇄ `PLAYER_NUKE_TARGETING`, `CPU_TURN`, 매 공격 후 `RESOLVING_ATTACK`, 종료 시 `GAME_OVER`. 각 메서드는 허용된 상태에서만 동작하고 그 외에는 `null`/`false`를 돌려줍니다.

### ai.js 주요 함수

| 함수 | 설명 |
| --- | --- |
| `deduce(cells)` | 함선끼리 대각선으로도 붙을 수 없으므로 명중 칸의 대각선을 빈 바다로 추론 |
| `searchDensity` | 탐색 모드 확률 지도. 남은 함선이 미확인 칸에 놓일 수 있는 경우의 수를 칸마다 계산 |
| `targetCandidates` / `targetScores` | 추적 모드. 명중 1칸이면 상하좌우, 2칸 이상이면 방향을 추정해 양 끝을 공격 |
| `chooseNukeCenter` | 확률 지도 + 추적 후보 가중치를 3×3 범위로 합산해 가장 높은 중심 선택 |
| `decide(view, hasNuke)` | 핵폭탄이 있으면 사용(보유 한도 1개라 아끼면 손해), 없으면 일반 포격 |

### ui.js

- 포격 후 0.45초 동안 결과를 보여 주며 입력을 막고, CPU는 포격 사이 약 0.8초 간격으로 행동합니다.
- 모든 지연 실행은 `later()`를 거치며, 새 게임마다 증가하는 `gen` 값이 다르면 실행하지 않습니다. 이전 게임에서 예약된 CPU 공격이 새 게임에서 실행되지 않습니다.

## 알려진 한계와 개선 가능 사항

- 화면이 좁으면(약 900px 미만) 두 격자가 위아래로 배치됩니다. PC 화면 기준으로 설계했습니다.
- 효과음은 첫 클릭 이후부터 재생됩니다(브라우저 자동재생 정책). 음소거 버튼은 없습니다.
- CPU는 핵폭탄을 얻자마자 사용합니다. 추적 중인 함선의 방향이 확정된 경우에는 일반 포격이 더 효율적일 수 있어, 상황별 보류 전략을 추가할 여지가 있습니다.
- CPU 탐색은 확률 지도 방식이라 강한 편입니다. 난이도 선택이 필요하면 체커보드/무작위 탐색을 섞는 옵션을 둘 수 있습니다.
