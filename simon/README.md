# 게임 개발 요청서: 따라하며 누르기

## 1. 게임 개요

- 게임 제목: 따라하며 누르기
- 게임 유형: 기억력 기반 순서 따라 누르기 게임 (Simon Says 방식)
- 개발 방식: HTML, CSS, JavaScript를 이용한 웹브라우저 게임
- 목표: 컴퓨터가 무작위로 제시하는 7개 버튼의 입력 순서를 기억하고, 제한시간 내에 동일한 순서로 입력하여 스테이지를 클리어하는 게임
- 별도 서버 없이 로컬 웹브라우저에서 실행할 수 있도록 개발한다.

## 2. 화면 구성

### 2.1 기본 화면

- 배경색은 검정색(#000000)으로 설정한다.
- 화면 중앙에 흰색 원형 버튼 7개를 북두칠성(Big Dipper)의 실제 별자리 형태와 유사하게 배치한다.
- 북두칠성의 국자 손잡이와 국자 부분이 시각적으로 구분되도록 배치한다.
- 7개의 버튼은 동일한 크기의 원형으로 구성한다.
- 기본 상태에서는 모든 버튼을 흰색으로 표시한다.
- 화면 크기가 달라져도 북두칠성의 형태와 버튼 간 상대적 위치가 유지되도록 한다.

### 2.2 게임 정보 표시

화면 왼쪽에 다음 정보를 위에서 아래 순서로 배치한다.

1. Stage: 현재 스테이지 번호
2. Time: 남은 제한시간 (초)
3. Score: 현재 누적 점수

모든 텍스트는 검정 배경에서 잘 보이도록 흰색으로 표시한다.

### 2.3 시작 화면

- 화면 중앙에 빨간색 `START` 버튼을 표시한다.
- START 버튼을 누르면 Stage 1이 시작된다.
- 게임 진행 중에는 START 버튼을 숨긴다.
- 컴퓨터가 순서를 보여주는 동안 플레이어는 입력할 수 없다.

## 3. 원형 버튼의 색상 및 음계

7개의 원형 버튼은 화면상 왼쪽에서 오른쪽 순서대로 다음 색상과 음계를 배정한다.

| 버튼 번호 | 색상 | 음계 |
|---|---|---|
| 1 | 빨강 | 도(C4) |
| 2 | 주황 | 레(D4) |
| 3 | 노랑 | 미(E4) |
| 4 | 초록 | 파(F4) |
| 5 | 파랑 | 솔(G4) |
| 6 | 남색 | 라(A4) |
| 7 | 보라 | 시(B4) |

- 평상시에는 모든 버튼이 흰색이다.
- 버튼이 활성화되면 지정된 색상으로 0.5초간 빛난다.
- 활성화와 동시에 지정된 음계의 소리가 출력된다.
- 소리는 Web Audio API를 이용하여 구현한다.
- 음계 소리는 각각 구별 가능해야 한다.
- 버튼의 색상 및 음계는 컴퓨터 시연과 플레이어 입력에서 동일하게 작동한다.
- 동일한 버튼이 연속으로 선택될 수도 있다.

## 4. 게임 진행 방식

### 4.1 스테이지 시작

1. 플레이어가 최초 START 버튼을 누르면 Stage 1을 시작한다.
2. 컴퓨터가 해당 스테이지 번호와 동일한 개수의 버튼을 무작위로 선택한다.
3. 선택된 순서에 따라 버튼을 하나씩 활성화한다.
4. 각 버튼은 0.5초 동안 색상과 음계를 출력한다.
5. 각 버튼 사이에는 0.3초의 간격을 둔다.
6. 컴퓨터가 전체 순서를 보여줄 때 플레이어의 버튼 입력은 차단한다.
7. 컴퓨터의 시연이 끝나면 화면 중앙에 `START`라는 안내 문구를 표시한다.
8. 안내 문구가 표시되는 순간부터 제한시간 카운트다운을 시작하고 플레이어 입력을 허용한다.

컴퓨터 시연이 끝났을 때 표시되는 START는 안내 문구이며, 최초 게임 시작 버튼과는 별개이다. 플레이어가 다시 START 버튼을 누를 필요는 없다.

### 4.2 스테이지별 입력 개수

각 스테이지에서 컴퓨터가 입력하는 버튼의 개수는 해당 스테이지 번호와 같다.

- Stage 1: 1개
- Stage 2: 2개
- Stage 3: 3개
- Stage 4: 4개
- Stage 5: 5개
- Stage N: N개

각 스테이지마다 새로운 무작위 입력 순서를 생성한다.

이전 스테이지의 입력 순서는 다음 스테이지에 누적하지 않는다.

### 4.3 제한시간

제한시간은 다음 공식으로 계산한다.

제한시간(초) = 5 + (현재 스테이지에서 입력해야 하는 버튼 개수 × 2)

예시:

| Stage | 버튼 입력 개수 | 제한시간 |
|---|---|---|
| 1 | 1 | 7초 |
| 2 | 2 | 9초 |
| 3 | 3 | 11초 |
| 4 | 4 | 13초 |
| 5 | 5 | 15초 |
| 10 | 10 | 25초 |

- 제한시간은 컴퓨터의 시연이 모두 끝난 후 시작한다.
- 남은 시간은 실시간으로 화면에 표시한다.
- 남은 시간이 0초가 되면 입력을 차단하고 실패 처리한다.
- 모든 입력을 제한시간 내에 완료하면 카운트다운을 즉시 중지한다.

### 4.4 플레이어 입력

1. 플레이어는 컴퓨터가 제시한 버튼 순서를 기억한다.
2. 입력이 허용되면 원형 버튼을 마우스로 클릭한다.
3. 클릭한 버튼은 지정된 색상으로 0.5초간 빛나고 해당 음계를 출력한다.
4. 클릭할 때마다 컴퓨터가 제시한 순서와 비교한다.
5. 올바른 버튼을 누르면 다음 입력을 기다린다.
6. 하나라도 잘못 누르면 즉시 실패 처리한다.
7. 모든 버튼을 올바른 순서로 누르면 스테이지를 클리어한다.

## 5. 점수 계산

스테이지 클리어 시 다음 공식으로 점수를 계산한다.

획득 점수 = 1 + 남은 제한시간(초)

- 남은 시간은 소수점 이하를 버림 처리하여 정수로 계산한다.
- 예: 남은 시간이 4.8초이면 4초로 계산하여 5점을 획득한다.
- 점수는 스테이지마다 누적한다.
- 실패한 스테이지에서는 점수를 획득하지 않는다.
- 실패 후 재도전 시 기존 누적 점수는 유지하되, 실패한 시도에서는 점수를 추가하지 않는다.

예시:

Stage 1을 남은 시간 5.2초에 클리어했다면 6점을 획득한다.

Stage 2를 남은 시간 3.7초에 클리어했다면 4점을 획득한다.

누적 점수는 10점이 된다.

## 6. 스테이지 클리어

플레이어가 제한시간 내에 모든 버튼을 정확한 순서로 입력하면 다음과 같이 처리한다.

1. 타이머 정지
2. 점수 계산 및 누적
3. 화면 중앙에 `STAGE CLEAR` 표시
4. 1.5초 후 다음 스테이지로 자동 이동
5. 스테이지 번호 1 증가
6. 새로운 무작위 버튼 순서 생성
7. 컴퓨터가 다음 스테이지의 순서를 시연

게임에는 최대 스테이지 제한을 두지 않는다.

## 7. 실패 처리

다음 조건 중 하나라도 발생하면 즉시 실패 처리한다.

- 플레이어가 컴퓨터의 순서와 다른 버튼을 클릭한 경우
- 제한시간 내에 모든 입력을 완료하지 못한 경우

실패 시 다음과 같이 처리한다.

1. 타이머 정지
2. 플레이어 입력 차단
3. 화면 중앙에 빨간색 `FAILED` 표시
4. 현재 스테이지 번호 및 누적 점수 표시
5. `RETRY` 버튼과 `메인화면` 버튼 표시

### 7.1 RETRY 버튼

- 실패한 스테이지를 다시 시작한다.
- 스테이지 번호는 유지한다.
- 누적 점수는 유지한다.
- 해당 스테이지의 제한시간을 초기화한다.
- 컴퓨터가 새로운 무작위 입력 순서를 생성하여 다시 시연한다.
- 실패한 시도에 대한 점수는 추가하지 않는다.

### 7.2 메인화면 버튼

- 최초 시작 화면으로 돌아간다.
- 스테이지를 1로 초기화한다.
- 누적 점수를 0으로 초기화한다.
- 남은 시간을 초기화한다.
- 화면 중앙에 빨간색 START 버튼을 표시한다.

## 8. 게임 상태 관리

게임 상태를 다음과 같이 구분하여 구현한다.

| 상태 | 의미 | 플레이어 입력 |
|---|---|---|
| READY | 최초 시작 화면 | 불가능 |
| COMPUTER_TURN | 컴퓨터가 순서를 시연 중 | 불가능 |
| PLAYER_TURN | 플레이어 입력 대기 중 | 가능 |
| STAGE_CLEAR | 스테이지 클리어 | 불가능 |
| FAILED | 스테이지 실패 | 불가능 |

상태에 따라 화면 표시, 버튼 입력, 타이머 실행 여부를 명확하게 제어한다.

게임 상태가 변경될 때 이전 상태의 타이머나 애니메이션이 중복 실행되지 않도록 한다.

## 9. 개발 시 요구사항

- HTML, CSS, JavaScript를 사용한다.
- 별도의 유료 API나 외부 서버 없이 작동하도록 한다.
- Chrome 및 Whale 브라우저에서 정상 작동해야 한다.
- 원형 버튼은 마우스 클릭이 가능해야 한다.
- 여러 버튼이 동시에 활성화되는 오류가 없어야 한다.
- 컴퓨터 시연 중 플레이어의 클릭은 무시한다.
- 플레이어가 빠르게 연속 클릭해도 입력 순서가 정확하게 판정되어야 한다.
- 타이머는 실제 경과시간을 기준으로 계산하여 시간 누적 오차를 줄인다.
- 화면 크기가 변경되어도 북두칠성 배치가 유지되어야 한다.
- 코드에는 주요 게임 로직을 이해할 수 있도록 주석을 작성한다.

## 10. 완성 후 테스트

다음 항목을 확인한다.

1. START 버튼을 누르면 Stage 1이 시작되는가?
2. 컴퓨터가 각 스테이지에 맞는 개수의 버튼을 시연하는가?
3. 모든 버튼에서 올바른 색상과 음계가 출력되는가?
4. 컴퓨터 시연 중 플레이어 입력이 차단되는가?
5. 컴퓨터 시연이 종료된 다음 제한시간이 시작되는가?
6. 올바른 순서로 누르면 스테이지가 클리어되는가?
7. 잘못된 버튼을 누르면 즉시 FAILED가 표시되는가?
8. 시간이 종료되면 더 이상 버튼을 누를 수 없는가?
9. 남은 시간에 따른 점수가 정확히 계산되는가?
10. RETRY 시 현재 스테이지와 누적 점수가 유지되는가?
11. 메인화면 복귀 시 모든 게임 상태가 초기화되는가?
12. 스테이지가 증가해도 타이머와 입력 판정이 정상 작동하는가?

## 11. 최종 결과물

실제로 실행 가능한 웹게임을 완성한다.

- HTML, CSS, JavaScript 소스코드 작성
- 파일별 역할 설명
- 로컬 컴퓨터에서 실행하는 방법 안내
- 게임 규칙과 조작 방법 간단히 안내
- 테스트 결과 및 남아 있는 문제 보고

가능하면 외부 라이브러리를 사용하지 않고 순수 JavaScript로 구현한다.

설계 및 구현 과정에서 요구사항에 없는 기능을 임의로 추가하지 않는다.
